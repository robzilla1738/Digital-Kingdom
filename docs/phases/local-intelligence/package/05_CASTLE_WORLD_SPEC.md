# Operational castle and local-world experience

## 1. Preserve the current visual foundation

The existing four-workspace shell and ten architectural modules remain. This is not another theme reset. Keep the current type hierarchy, quiet evidence tables, explicit uncertainty, camera focus controls, roof-off support and 2D fallback. Improve the world’s meaning and detail.

Target: a coherent stone/slate architectural miniature that reveals actual technical structure. New scenes should feel composed, with deliberate courtyards and readable buildings. No first-person navigation requirement, constant attack particles, or badge overload.

The current surface registry names six additional families but does not make every family a rendered provider-integrated building. This phase implements those families as reusable architecture linked to supported local/declared records. Rendering does not upgrade their telemetry support.

## 2. Semantic levels

| Level | Visible | Navigation |
|---|---|---|
| Realm | Local run environments, case attention and visibility summaries | Click environment, search asset, open case |
| Environment | Districts and major authority/data/delivery relationships | Select layer and focus scope |
| District | Logical services and important controls | Stable framing, expand membership |
| Structure | Service or resource with current and selected historical state | Open technical interior |
| Interior | Routes, grants, objects, tools, artifacts or tests | Select exact record, query, compare |
| Evidence | Supporting/counter records, coverage, revisions | Shared inspector/workbench, not another world |

Zoom is semantic: distant views suppress detail without hiding the existence of relevant findings or unobserved resources. All grouped assets remain searchable. Selection stays a canonical ID, not a mesh index.

## 3. Six architectural families

### DNS registry

A compact registry hall with a signboard court, restrained clock/bell element and separate marker positions for names/records. A record interior lists name, type, target, declared/observed source and validity. It does not perform Internet discovery in this phase. Locally declared route aliases are labeled as such.

### Dispatch house

A long low warehouse with two clear loading bays and a central sorting roof. Producers and consumers use opposite connection anchors. The interior shows topic/queue, permissions, message correlation and observer gaps. Decorative packages do not become messages; only recorded operations animate delivery.

### Key registry

A small fortified administrative hall with a recessed key-room and record shelves, not a vault overflowing with literal API keys. The interior shows principals, scoped grants, token references, expiration and condition badges. Secret values are never rendered. A disabled key with a remaining child grant is visible as separate authority, not one green lock.

### Supply depot

A stepped storage complex with a loading platform, artifact shelving silhouette and crane/hoist detail contained inside its footprint. Its interior shows source revision, build identity, digest, provenance and running artifact relation. A valid signature receives a provenance label, not a malware-free shield.

### Archive

A broad stone archive with two roof heights and a clear protected entrance. Use it for data collections, retrieval stores and backup references. Interior tabs distinguish data classification, access, retrieval provenance, retention and restore results. Never combine backup configuration with actual restoration status.

### Outpost

A modest isolated tower/pavilion connected by an explicitly labeled logical relationship. Represents a registered synthetic endpoint/worker/partner in this phase. No implied geolocation, attack origin or public scanning. The external boundary and visibility limit are visible on selection.

### Geometry contracts

Every module has a catalog ID/version, footprint, height, origin, connection anchors, label anchors, roof group, interior anchor, selection proxy, three detail levels, bounding tests, material reuse and license provenance. Use current kit units and budgets rather than inventing incompatible dimensions. Updating the kit updates its manifest and source-bound contact sheet.

Architecture must have actual depth: recessed openings, roof overhangs, thickness and recognizable structural detail. Low detail may simplify these; high detail must not introduce out-of-bounds click blockers. All new families require actual rendered comparison images and interaction tests. An LLM-generated concept image does not satisfy this requirement.

## 4. Technical interiors

Interiors are selectable architectural cutaways plus an accessible record panel, not a miniature game. The investigator can jump directly to the relevant item.

| Interior | Operational objects | Useful actions |
|---|---|---|
| Service | Host/method/route templates, owner, deployment | Resolve route, find activity, compare candidate |
| Identity | Principals, sessions, keys, grants, conditions | Explore permission, inspect use, track descendants |
| Data | Collections, tenant/resource scope, audit capability | Query reads, inspect coverage, verify synthetic isolation |
| Agent | Run, policy, tool invocation, execution, effect | Open obligation, inspect denial/effect discrepancy |
| Delivery | Commit, workflow, artifact, deployment | Check digest/provenance, compare running candidate |
| Control | Declared configuration, tests, stale/failed status | Open receipt, run an authorized local test |

Every object opens the same record as its 2D/list equivalent. Relevant IDs remain visible and copyable. Counterevidence never disappears when the camera zooms out.

## 5. World layers

Separate topology, identity authority, data, delivery, agent actions, evidence, coverage and proposals. A single layer switch should clarify a case rather than produce a second incompatible graph.

Use visually distinct line patterns, labels and endpoint semantics:

- Declared relationship: muted patterned line with declaration source.
- Observed operation: directional mark tied to event IDs and interval.
- Conditional authority: patterned line with a condition marker.
- Hypothesis: explicit hypothesis label; off by default outside a case.
- Verified local boundary: test badge with scope and date, not a generic shield.
- Unknown coverage: textured/hatched overlay and text, not healthy green.

A shared source count is not an affected-asset count. A control that covers one route should not light up the entire building as protected.

## 6. Case focus

Selecting a case highlights only its scoped entities and relationships. Related but unproven links remain labeled hypotheses. An unlinked event may be added through the investigation workbench, with versioned provenance.

The sidebar becomes a case map: observed facts, open obligations, important contradictions, repair candidates, verification. The world maintains its stable layout. A camera animation is explicit, cancelable, short and disabled under reduced motion.

The scene never draws an identifiable human attacker. An activity marker represents a recorded event or investigation cluster. Shared network addresses do not become avatars inside another user’s room.

## 7. Baseline/branch comparison

Use synchronized cameras and stable coordinates. Show changes through an added/removed/modified list and bounded ghost geometry. A branch header names model-only versus executed-local state and both revisions.

A modeled permission reduction may remove a conditional edge in the branch, but no shield is awarded until an actual supported test result exists. Switching branches does not switch the current ingestion project or replay historical source configuration as current.

Expose “why different”: precise grants, route fields, tool permissions, artifact digest or observer settings. Comparison can be exported with uncertainty intact.

## 8. Run and mission controls

Keep run controls in a compact contextual bar: start/pause/resume, snapshot/clone, stop, clean up, export and mode badge. Only show actions the caller can actually perform. Distinguish stimulus paused, service stopped and stream disconnected.

Creating a mission previews every component, source, synthetic dataset, proposed operation, resource budget and unknown. A user can cancel before starting. Failed creation preserves the plan draft and reports any partially allocated resources and cleanup status.

The same workspace supports ordinary evidence with no lab controls. The lab is an additional environment mode, not a replacement for the product.

## 9. AI affordances

An “Investigate this” action opens the scoped contract and identifies the mode/authority. It does not silently launch paid model calls. A draft panel displays what the agent retrieved, which obligations remain, the proposed claim and the supporting records.

An “Explain” response cites data and is labeled a draft where semantic support is not mechanically checked. A “Compare fixes” action generates finite candidates. An “Apply locally” action is visible only for a run-owned target with a valid lease and separate controller; it is never an approval shortcut for non-lab data.

## 10. Rendering and interaction gates

Record build, browser, viewport, renderer/device, quality settings, graph size, active labels and observed timings. Use existing resource-lifetime diagnostics. Do not multiply materials per asset or keep abandoned renderer owners alive.

Planned local gates include 10, 50 and 200 logical assets with appropriate grouping. At 200 assets, the product may use district aggregation and still expose every asset in searchable lists; it need not render 200 detailed interiors simultaneously. Set measured environment-specific budgets before the final run. Never call software WebGL a physical-GPU benchmark.

Required views: overview, each new family, roof-off, selected route, selected grant, agent effect, missing coverage, comparison branch, failed verification, narrow evidence, keyboard navigation, reduced motion, 2D parity, WebGL recovery and repeated project/run switching.

Existing visual baselines are not overwritten automatically. Record intentional changes and inspect actual pixels. Human architectural approval, manual screen-reader evaluation and physical hardware acceptance remain deferred; automated checks must not impersonate those approvals.
