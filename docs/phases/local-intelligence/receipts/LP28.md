# LP28 — Package evidence-only and training capsules (receipt)

Milestone M7, worktree `DK-m7` (branch `phase/li-m7`), pushed directly to `phase/local-intelligence` as 72383a6.
Depends on LP23 (regression descriptors, local repair links) and LP25 (private truth / oracle separation). CI is
recorded in STATUS.json (`packages[LP28]`).

Reused: the R03.1 signed case export (`Cases.export`: pinned bundles, independent events, history, `unavailable`
list, section digests), the stored scene digest/layout version and graph revision, LP23 `checkRegression` and the
`local_repair_links` documents, the R10.2 backup's scrypt parameters, `hmac`/`sha256`, and the LP25 rule that the
investigator side never holds private truth (so the server builds evidence-only capsules only; a training capsule is
built by the evaluation side with the oracle in hand).

## What changed
- Contract `dk.local.capsule.v1` manifest (`packages/contracts/schemas/local/capsule-manifest.v1.schema.json`,
  `validateCapsuleManifest`): kind `evidence_only | training`, capsule id, source (hashed project ref, case id/version,
  data origin), entries (allowlisted path, SHA-256, bytes, role), evidence references, absent records, scene revision,
  regression ids, `sealed` (null for evidence-only; for training exactly one `sealed/oracle.dkseal`, AES-256-GCM,
  scrypt KDF, ciphertext digest, plaintext commitment, `separated: true`, `training_and_evaluation_only`), excluded
  categories, the integrity statement and `local_only_no_third_party_storage`. Semantic checks: an evidence-only
  capsule has no sealed entry or metadata; a training capsule has exactly one; role and location agree.
- `apps/server/src/capsule.ts`: gzip'd ustar writer/reader with no dependencies. `inspectArchive` works entirely in
  memory before anything is accepted: bounded gunzip (64 MB) + ratio limit (200:1 above 1 MB), header checksums,
  regular files only (hard/symbolic links, directories, devices refused), path checks (absolute, drive letters,
  backslashes, `..`/`.` segments, allowlisted layout and `.json`/`.dkseal` only), executable/setuid mode bits,
  executable or nested-archive magic (ELF, PE, Mach-O, shebang, zip, wasm), per-entry size (8 MB), entry count (512),
  duplicates. `buildCapsule` refuses oracle data in an evidence-only capsule, scans every entry for tokens/secrets/
  provider credential fields/Digital Kingdom tokens/lab sessions and passwords/oracle fields/font files (categories
  only in errors), refuses oracle values leaking into the evidence part of a training capsule, seals the oracle
  separately, drops the source server's export signature, signs the manifest (HMAC, optional). `importCapsule`
  validates the manifest schema, refuses unlisted/missing entries and digest mismatches, re-scans content, re-checks
  the case export's own section digests, re-derives evidence references and absent records from the evidence and
  compares them with the manifest, validates regression descriptors, reports the origin signature as `valid`,
  `not_from_this_instance`, `not_checked` or `absent`, and opens a seal only with a passphrase (commitment checked).
- Server: `POST /api/projects/:p/cases/:id/capsule` (analyst; evidence-only, includes linked LP23 regressions and LP22
  verifications, audited), `POST /api/capsules/import` (admin; stores the checked capsule in its own namespace
  `capsule:<id>` in `capsule_imports`, never touching project data; a sealed attachment is never opened or stored in
  plaintext), `GET /api/capsules/:ns` (viewer).
- Integrity wording (A4) in the manifest, the signature entry and every import result: "integrity and origin relative to
  the exporting instance … not proof of truth, not proof of completeness and not an independent approval".

## Limits
- The HMAC signature proves origin only to an instance holding the same secret; there is no public-key signature.
- Import stores the checked capsule as a read-only record in a separate namespace; it does not re-materialize events or
  findings into a project (the case is reproduced as its exported record and references, not as live data).
- Training capsules are built through the library by the evaluation side; there is no server route (the server never
  holds private truth). No web UI button yet (`apps/web/src/inspector/actions.tsx` unchanged).
- Content scanning is pattern-based (secrets, tokens, credential fields, oracle fields, fonts); it is a guard, not a
  proof that nothing sensitive remains. No model call; AI execution not exercised.
