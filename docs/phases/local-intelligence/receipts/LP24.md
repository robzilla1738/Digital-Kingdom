## What changed (new files, `eval/local/`)

- `modes.ts` — `declareMode`: `scripted`, `native_agent`, `local_model`, `approved_provider`. A mode must be named;
  nothing is chosen by default. `approved_provider` needs `DK_LI_ROUTE=ai-gateway`, `DK_LI_MODEL`, a positive
  `DK_LI_CAP_USD`, `DK_LI_APPROVED=local-intelligence-phase` (this phase's approval) and a credential; a partial
  configuration — including the historical `DK_EVAL_V2_APPROVED` — resolves to `not_exercised` with the reason, never a
  fallback. `local_model` must be loopback. Labels follow capabilities, not claims: `scripted`, `restricted_model` (MCP
  tools only) or `development_assisted` (any repository/filesystem/shell/network access or prior fixture exposure; every
  native agent). Claiming `blinded` with such capabilities throws.
- `controller.ts` — the run controller: isolated in-memory Digital Kingdom server, a supervisor-owned local world, the
  LP07 scenario (time scale 1), a case with a fixed public task per blueprint (`PUBLIC_TASKS`, `li-task-1`: scope and
  response class only), all product findings linked, and the deterministic guided planner (analyst SERVICE token held by
  the controller) opening the contract and running the bounded job. The investigator gets a PUBLIC handle only (URL,
  project-scoped service viewer token, project, case, task, interval). The private handle (document, seed, truth, a
  0600 oracle file with a random leakage canary in the run directory under the OS temp root) never leaves the process.
- `recorder.ts` / `trace.ts` — the scoped MCP connection per condition (C1 full investigation tools, C2 event tools,
  C3 guided `investigation-read`) and the evidence-exposure recorder (`dk.local.investigation_trace.v1`: tool list,
  requests, responses, denials, final claims; token redacted). `exposure()` counts a record only when the full stored
  record, or an LP10 packet record with the same digest, was returned — a mentioned id is not exposure.
- `scripted.ts` — the deterministic investigator (no model) for all three conditions.
- `model-agent.ts` — the restricted model investigator: fresh conversation, the condition's MCP tools only, every request
  pre-reserved via `chat`'s budget; provider reasoning payloads are dropped (never stored, never replayed).
- `answer.ts` — the common structured answer `dk.local.eval_answer.v1` (per request: outcome, independent effect,
  boundary violation, cited event ids).
- `native-agent.ts` + `mcp-proxy.ts` — the bring-your-agent kit: `tsx eval/local/native-agent.ts --scenario LW-01
  --dir <dir outside the repo>` writes `TASK.md` (public task, answer shape, `development_assisted` label) and
  `mcp.json` (mcpServers entry, mode 0600) that launches a recording proxy in front of the real `investigation-read`
  server; the proxy relays JSON-RPC unchanged and appends observable tool I/O to `trace.jsonl` (0600). The run waits for
  `answer.json` and grades it.

## Tests (executed) — `eval/test/li-lp24-bring-your-agent.test.ts`, 5 tests

- **A1** (2): scripted investigators for C1/C2/C3 reach the LW-01 world over real stdio subprocesses with a scoped
  service viewer token and answer exactly the 5 in-scope requests with the executed outcomes; C3 offers exactly the 8
  read tools, `dk_session` reports role viewer and `writes_effective: false`; revoking the token makes the same live
  session's next call fail (`authority_refused` recorded). The native-agent kit's own `mcp.json` entry is launched by a
  stand-in client through the proxy: tools listed, a packet read, an unknown `read_file` call refused, and the trace file
  (0600) contains the tool I/O and no token; `TASK.md` contains the public task and no seed.
- **A2** (1): no mode / an unknown mode throws; `approved_provider` with nothing, with only a key, or with the historical
  v2 approval is `not_exercised` (reason names the missing pieces); an unknown route throws; a remote `local_model` URL
  throws; only a complete configuration is `ready` with `ai_checks: exercised`.
- **A3** (1): every `native_agent` is `development_assisted` (even if it claims no repository access) and cannot be
  declared blinded; `local_model` with repository access is relabelled `development_assisted`; the kit's `TASK.md` says so.
- **A4** (1): a model investigator against a loopback stand-in provider (no spend) whose every reply carries a reasoning
  payload: the trace and turns contain no reasoning payload/field and no token, the payload is not replayed to the
  provider, trace entries are only `tools_list`/`tool_call`, and the MCP subprocess environment is exactly
  `DK_URL, DK_TOKEN, DK_PROJECT, DK_MCP_PROFILE`.

## Limits

- A native coding agent run is `development_assisted` by construction; no blinded native-agent run is claimed. The kit
  was exercised with a stand-in stdio client in the test, not with an external coding agent (none is attached to CI).
- The declared real route (`approved_provider`, `meta/muse-spark-1.3-contributor` over the AI Gateway) was exercised in
  LP26's recorded runs (smoke + preregistered comparison); see the LP26 receipt for the records and exact spend. LP24's
  own tests make no paid call.
- `local_model` was exercised only against the loopback stand-in in tests; no real local model endpoint exists here.
