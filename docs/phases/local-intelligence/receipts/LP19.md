# LP19 — Add baseline-versus-repair world comparison (receipt)

Milestone M4, branch `phase/li-m4`. Status: **implemented_locally_verified** for the castle comparison overlay; the 2D-graph overlay and time-known/time-occurred replay scope of a comparison are not implemented (see Limitations).

Reused: LP13 `analysis_comparisons` (append-only, receipt-bound), `Exploration.get/baseline`, `keyOf`, the stored
baseline scene (LP16 layout). LP14 repair candidates feed comparisons through the same LP13 path; no LP22 verification
exists on this branch, so executed-local results are a separate, explicitly empty list.

## Substage 1 — `dk.world_comparison.v1`
- `apps/server/src/world-comparison.ts` + `GET /api/projects/:p/analysis/comparisons/:id/world` (viewer, read-only;
  `?download=1` adds an attachment header for export). Each changed element key (added / removed / modified) is
  resolved to its asset(s) from declared attributes only (asset_id, asset_ids, source/target, provider owner, route
  owner) and the asset's BASELINE room is marked added / removed / changed with the exact element refs at its baseline
  position ("common layout": nothing recompiled, re-placed or stored). Changes that do not resolve to an asset stay in
  the change list with a warning. Both revisions are identified (baseline state hash, graph revision, scene digest,
  layout version, current?; candidate state hash, namespace, receipt digest). Model-only access results carry
  `executed:false, verified:false, basis: configured_permission`; condition keys and unassessed paths are kept; a
  changed baseline is warned about, never silently re-based.
- `apps/server/test/phase-lp19-world-comparison.test.ts` 1/1: A1 viewing leaves every baseline table, coverage and
  the baseline state hash unchanged; A2 exact refs per change and per room at the baseline position, unresolved
  conditions preserved; A3 model-only never executed/verified, executed-local separate and empty with the
  "simulated blocked path is not a verified executed control" note; A4 both revisions + receipt digest, export
  header, stale-baseline warning, 404.

## Substage 2 — castle comparison overlay
- `apps/web/src/castle/ComparisonOverlay.tsx`: `?cmp=<comparison id>` loads the read-only world comparison through
  `ServerActions.worldComparison`. Ghost badges ("Δ api · changed in repair · model only", dashed, glyph + text) sit
  on the SAME baseline rooms with the same layout and camera; a "Baseline vs repair · model only" panel lists both
  revisions, warnings, every change with its exact key, op, unresolved conditions and buttons that select the
  canonical asset record, model-only access as "not executed · not verified", the separate executed-local list,
  and a JSON export of the exact record.
- `e2e/comparison-redesign.spec.ts` (API-backed isolated synthetic server, SwiftShader) 1/1 passed: both revision
  hashes shown, every change row has its op, executed-local note, "never a security fact", one badge per changed
  baseline room with the right change, all canonical asset labels still present, a change row selects the
  canonical asset, and graph/scene/sources/coverage/findings + analysis state hash are unchanged afterwards.
  Screenshot inspected: `lp19-baseline-vs-repair-castle.png` (first render's badges did not name their room; fixed).
  Report: `artifacts/phase-local-intelligence/M4/lp19-comparison-verification.json`.

## Limitations
- Castle overlay only; the 2D graph does not yet draw the comparison (the change list and selections are shared).
- No time-known/time-occurred replay of a comparison; the comparison describes the stored baseline state it was
  made against and warns when that baseline is no longer current.
- No LP22 verification exists on this branch, so executed-local results are always the explicit empty list here.
- Software WebGL only; no GPU claim.
