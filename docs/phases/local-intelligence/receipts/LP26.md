## LP26.1 — coverage defect (decision D-LP26-4)

Finding: in v1 every C3 coverage obligation came back `unavailable` ("3 minute(s) with no capable live observer")
while the observers were registered and reporting. Two causes, both reproduced by failing tests first:

1. **Product (apps/server/src/coverage-history.ts).** Before a source's first receipt, liveness was judged from the
   start of the question interval, so a source registered at R whose first receipt came 5 ms later was reported
   "silent for more than 600s (no receipts)" for [interval start, first receipt). Fix: a first receipt within the
   freshness threshold of registration makes [registration, first receipt) live, exactly like any gap between two
   receipts. Unchanged: time before registration ("not yet registered"), a source that never reported, a first report
   later than the threshold, the future, outages, disablement, capability, sampling and retention all stay unknown.
   `apps/server/test/phase-lp26-1-coverage.test.ts` (5 tests; 3 failed before the fix with 5–10 ms "silent" slivers).
2. **Harness (eval/local/controller.ts).** The case interval was [world start − 60 s, setup + 120 s]: a minute before
   any observer existed and two minutes in the future, which coverage honestly reports as unknown. Fix: the case
   interval is the run itself — [the later of every source's `created_at` and first-revision `effective_at`, the moment
   the last record was stored]; the controller refuses to start if any stored record falls outside it.
   `eval/test/li-lp26-1-coverage.test.ts` (3 tests): the effect observer's obligation is `satisfied` on LW-03 (failed
   before; also fails with only one of the two fixes), an observer disabled for the interval still leaves it
   `unavailable` (negative control), and the v1 interval (`legacyInterval`) is still honestly `unavailable`.
   798d8e2 hardened the interval start after CI run 40060841243 hit a ms-level `created_at`/`effective_at` race.

After the fix (local probe, all three dev documents): observer-backed obligations are satisfied; those that stay
unavailable are truthful — a scheduled observer outage (LW-01 audit), a source that cannot report the event class
(capability), no configured source, and recipe windows of ±1 h around a finding in a world that existed for < 1 s.

## Limitations

- Synthetic local laboratory (three blueprints); no production, provider or real-identity claim.
- v1 is incomplete (26/54 model records; no critique); its held-out counts are small. The follow-up uses 1
  repetition and burned held-out documents; the operator who wrote the generator, referee and tasks also wrote the
  product (not operator-blinded). No significance test, no pooled superiority claim.
- Same model family for the (lost) critique; human review deferred (EXT05). Nothing is approved.
- The follow-up ran on a159fe0 code, before 798d8e2. In its C3 traces every effect-observer obligation seen as
  `unavailable` (LW-01, held-out lh-4c68a14c8c, lh-e96cf153b3, lh-ec4ef9709a) is on a document with a scheduled
  observer outage; the ms registration race fixed in 798d8e2 was possible in principle but is not needed to explain
  any result.
