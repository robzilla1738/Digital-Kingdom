# LP20 — Run-scoped local authority leases (receipt)

Milestone M5, branch `phase/li-m5` (worktree `DK-m5`), based on `origin/phase/local-intelligence` 749fd61 (M0–M3
CI-verified). Commit and CI run are recorded in STATUS.json (`packages[LP20]`).

Reused: the LP05 supervisor (run tokens, `authorize`, run-owned resources, monotonic clock, private truth, halt
revocation), the LP14 `dk.local.repair_plan.v1` contract and its validator (plan-only, five action types, one
reference parameter each), `canonicalJson`, R08.2's principle that a changed digest cannot reuse an approval, and
the server's existing human-admin containment decision path (unchanged).

## What changed

- Contract `dk.local.lab_lease.v1` (`packages/contracts/schemas/local/lab-lease.v1.schema.json`,
  `packages/contracts/src/lab.ts`, generated `validateLabLease`): its own namespace `dk.local.lab_authorization`;
  run, project, plan id, canonical plan digest, baseline/candidate digests, controller identity, per action type /
  registered target / parameter digest / expected target revision, issue and expiry times, TTL (100 ms–15 min),
  operation budget; constants `issuer: supervisor`, `approval_kind: local_lab_lease`,
  `counts_as_human_approval: false`, `authorizes: typed_repair_actions_on_run_owned_disposable_resources`,
  `production_path: not_authorized`; no unknown fields. `isHumanApproval()` is constant `false` for anything the
  local phase handles.
- `packages/local-world/src/runtime/lease.ts` — `LeaseRegistry`:
  - issuance (operator only): supervisor must be in `leased` mode; run must be one of this supervisor's active
    runs; plan must validate (plan-only, unexpired) and name that run; controller must be a valid controller token
    of that run carrying `repair_execute` only; every target must be a resource of the supervisor-compiled world,
    never a provider identifier (ARN, 12-digit account, `i-…`/`sg-…`, `projects:` …), with the template the action
    type is reviewed for; references must have run-owned shapes (`policy:baseline|candidate` — never the weak
    variant —, `cred-N`, `grant-<12 hex>`, a 64-hex artifact digest, the observer's own id); the target's current
    revision must equal the plan's expected revision (precondition).
  - use-time `authorizeAction`: forged/unknown signature, expiry on the monotonic clock, revocation, kill switch,
    another run, a stopped run, another controller, a different canonical plan digest (any changed parameter), an
    action outside the lease, a stale target revision, a second use of an action (replay; only the journalled
    re-application of the same idempotency key after a crash is admissible, for LP21) and an exhausted budget are
    all refused. `consume` records a use before the operation is attempted; `confirmApplied` advances the expected
    revision for later actions on the same target; `authorizeCompensation` covers only actions this lease applied.
  - audit: every transition (`issued`, `refused`, `used`, `replay_refused`, `applied_confirmed`, `revoked`,
    `expired`, `exhausted`, `kill_switch`) is appended to the supervisor's audit log and, for run-scoped ones, the
    run's private truth.
- `supervisor.ts`:
  - `labActions` option, default `plan_only` (no lease can be issued).
  - one-time operator credential (`operatorCredential()`, `dkop_v1…`, handed out once). Only it can
    `issueControllerToken`, `issueLease`, `revokeLease` (any lease) and `killSwitch` (revokes everything and makes
    the supervisor plan-only for good). The holder may only give up its own lease. There is no extend/renew/approve
    operation.
  - new run action `repair_execute`, never part of the launcher's all-actions token and refused by ordinary
    `issue()`; a controller token carries exactly that action (no stimulus, configure or lifecycle).
  - halting a run (stop, abort, deadline) revokes its leases with its tokens; `revisionOf(id)` / `revisions()` give
    the current revision of every run resource (services' own revision, observers' health state).

The server is unchanged: no route accepts a lease or an operator credential, `/api/capabilities` still reports
`local_actions: plan_only, executor: not_available, lease_required: true` (the server has no executor; the leased
controller of LP21 is a library used by the launcher/tests inside a disposable run).

## Tests (executed) — `examples/reference-app/lp20-leases.test.ts`, 6 tests, negative cases first

Real supervisor + built-in services on 127.0.0.1; real Digital Kingdom server (Fastify inject) for A4.

- **LP20-A1** (2): a default supervisor refuses even the operator (plan-only) and audits it. With `leased`: the
  launcher's all-actions run token, an investigator run token, a controller token, a DK admin token, a DK service
  token, the lease itself, a forged operator credential and no credential cannot issue a lease, mint a controller,
  revoke a lease or pull the kill switch; a second `operatorCredential()` call throws; `issue()` refuses
  `repair_execute`; investigator/launcher tokens cannot be a lease's controller; the controller token cannot
  configure or send stimulus; no extend/renew/approve method exists; editing the returned lease object changes
  nothing (TTL, budget, human-approval flag stay); tokens re-signed for another lease id or with a bad MAC fail; a
  plan with `authority: execute` or an `approval` block, and an LP14 approval descriptor presented as a lease, are
  refused; ≥ 10 refusals and the issuance are in the audit log and the run's truth.
- **LP20-A2** (1): ARNs (`arn:aws:iam::…`, `arn:aws:s3:::…`), a 12-digit account, an EC2 instance id, a
  `projects:` id, an unregistered `prod-db` and `127.0.0.1:8787` are refused; plans for another supervisor's run,
  runs this supervisor never created and an unknown run id are refused; forged lab metadata (`lab`, `owner`,
  `supervisor_owned`, `lab_owned`, an extra `endpoint` parameter) is a schema violation; wrong template per action
  type, the weak policy variant and a foreign observer reference are refused; a `dk.response_plan.v1` is not a
  local plan; the supported lease validates and binds `api` at `api:policy-baseline-r1`.
- **LP20-A3** (2): a stale expected revision is refused at issuance; a 120 ms lease expires on the monotonic clock
  while `Date` is frozen; changed parameters and a changed control list (different digest), an unleased action and
  another controller identity are refused; a target reconfigured after issuance is `stale` (and stays stale after
  being changed back, since revisions only move forward); a used action cannot be used again (replay), and the
  same lease on a clone run is refused; operator revocation and the kill switch revoke, after which issuance is
  plan-only; stopping the run revokes its leases.
- **LP20-A4** (1): the lease's constants, `isHumanApproval(...) === false` even for an object claiming human
  approval, and the validator rejecting `counts_as_human_approval: true`, `production_path: authorized` or an
  `approved_by` field; on the server, the lease, the operator credential and the controller token are not bearer
  principals (401) for the existing containment decision; an analyst carrying the lease in the body is still 403
  and the request stays unapproved; no lease/lab-execution route exists (404); runtime policy is unchanged; no
  server, MCP or web source references the lease, operator credential, controller identity or `repair_execute`.

Also re-run unchanged: `packages/local-world` (LP04/LP05), `lp05-legacy-runner`, `phase-lp03-contracts`,
`phase-lp14-repairs` — 65 tests passed with LP20's 6.

## Limits

- Trusted host-process mode (LP05): the supervisor, registry and controller share one process. The operator
  credential is a one-time in-process capability, not an OS-level separation; untrusted code must not run in it.
- No human approval is recorded or simulated anywhere; production-facing approval remains the existing
  human-admin path, and recording human approval for repairs stays deferred (EXT05).
- No model call; AI execution not exercised.
