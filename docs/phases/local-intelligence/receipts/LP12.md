## What changed

- `apps/server/src/investigation/workbench.ts` — one read model `dk.case_workbench.v1`
  (`GET /api/projects/:p/cases/:id/workbench`, viewer): case progress (contract readiness and obligation states),
  evidence/coverage questions, competing hypotheses side by side, counter records listed before supporting records,
  failed or partial queries, uncertainty (assessable negative claims, coverage gaps anchored to assets), the next
  bounded action, a five-part summary (never one opaque score) and agent proposals with a per-case proposal version,
  their check status, `accepted: false` and `affects_case_record: false`. It writes nothing.
- `cases.ts` — service principals (agents) cannot answer/settle questions or hypotheses, remove items others added,
  or resolve/close a case (403).
- Console: `CaseWorkbench.tsx` inside `CasesWorkspace.tsx`; one `AbortController` per selected case so changing cases
  aborts stale reads; unsaved drafts in an in-memory store scoped to project + case + field (`lib/caseDrafts.ts`),
  cleared with sensitive client state; shared anchors (`asset:`, `event:`, `finding:`) map castle selections to
  workbench rows (`lib/workbench.ts`).
