# LP04 — Compile local application blueprints (receipt)

Reused: `dk.local.world_plan.v1` + `validateWorldPlan` (LP03), `importCompose` / `importManifest` / `sanitizeId`
(graph-core importers), `routesFromOpenApi` (R09.1 edge pack, now exported as `@dk/graph-core/packs/edge`),
`matchDeclaredRoutes` (R00.3 route identity), `compileScene` + `defaultProposal` (trusted scene compiler with pins),
`validateGraph`. New domain boundary `packages/local-world` (`@dk/local-world`), as proposed by the phase spec §22.

## What changed

- `packages/local-world/src/catalog.ts` — reviewed catalog `dk-local-catalog-1`: the 11 plan templates, each with
  asset kind (observer = a source, not an asset), fixed route inventory, the event categories its own
  instrumentation reports and as which source kind, effect taps an independent observer can attach to, supported
  settings, and per-template / per-catalog sha256 digests. No template carries an image, command, port or URL.
- `src/blueprints.ts` — three reviewed blueprints: `saas-storefront@1` (ingress, auth, tenant API, tenant DB,
  queue, worker, artifact store, audit observer), `agent-workspace@1` (bounded workspace, tool gateway, retrieval
  store, allowed and blocked receivers, runtime reports, independent effect observer), `delivery-identity@1`
  (builder, artifact depot, deployed digest service, local credential issuer, observed use). Synthetic accounts and
  tenants are part of the reviewed blueprint.
- `src/compile.ts` — `instantiateBlueprint(bp, {seed})` → validated world plan carrying only
  `sha256("dk-local-seed:"+seed)`; `checkPlan` adds catalog semantics (reviewed catalog version, supported settings
  per template, nothing may depend on an observer, an observer must attach to an effect tap);
  `compileWorld(plan, {previousScene})` → logical graph (stable asset id = logical resource id), declared sources
  each with its own independence group, route ownership table (more than one owner ⇒ `ambiguous`), synthetic
  identities in `local-world:accounts`, per-asset observation table and explicit gap list, castle layout from the
  existing scene compiler, and `revision = lw-<sha256(catalog digest, plan digest)>`. `withResource` adds one
  catalog resource without touching others; `previewWorld` is the operator preview.
- `src/descriptors.ts` — `previewDescriptor` for untrusted Compose / OpenAPI / dk-manifest text: allowlisted
  fields only; executable/host keys (build, command, entrypoint, healthcheck, environment, env_file, volumes,
  privileged, network_mode, ports, extends, include, merge keys, …) listed as ignored with a reason; interpolation in
  identity-bearing fields, YAML custom tags, alias bombs, remote/file `$ref` rejected; local `$ref`, servers,
  callbacks, links, webhooks, `x-*` ignored explicitly; declaration provenance (`import:<format>:<digest>`); name
  equality reported as candidates only, never an identity mapping.
- `apps/server/src/local-world.ts` (registered from `app.ts`): `GET /api/local-world/catalog`,
  `POST /api/local-world/preview` (blueprint+seed or descriptor). Viewer role; pure read: no project, source,
  audit row or outbound request is created.
- `apps/server/test/phase-lp00-baseline.test.ts`: LP00-A2 hashes the frozen trees once and has a 90 s timeout —
  it timed out at 20 s (28.8 s) on this 2-CPU sandbox while another suite ran concurrently. Assertions unchanged.

## Limits

- Display names of synthetic accounts and blueprint resource names are looked up from the blueprint inferred from
  the plan id (`<blueprint>-v<n>`); a plan with a custom plan id compiles with ids as names and no synthetic
  accounts unless the blueprint is passed explicitly.
- The `world_plan.v1` template enum is fixed (LP03). The agent workspace itself is a `worker` resource (asset kind
  worker); no new template value was added to avoid a contract change.
- Preview is API + library; the console "Create local world" surface lands with LP06's setup view.
