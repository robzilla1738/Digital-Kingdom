## What changed

- **Incarnations (LP16-A2).** `CompiledScene.incarnations` (metadata outside the geometry digest; absent on scenes
  stored before LP16). An asset id removed and later recreated, or whose declared provider identity changes, becomes a
  new incarnation `<id>~<n+1>`; the replaced one is retired into `historical_rooms` with its own `incarnation_id` and
  last position. A legacy stored scene adopts its current assets as `~1` instead of re-identifying them.
  `locateAsset()`; `GET …/scene/locate/:asset[?incarnation=]` lists every incarnation and resolves each to its own
  location; archived placements are never live structures.
- **Layout versions and previewed reflow (LP16-A1).** Append-only `scene_layouts` (migration `WORLD_LAYOUT_MIGRATION`):
  every saved layout change records the layout version, scene digest, reason (`graph` / `proposal` / `reflow`) and a
  room-by-room `layoutDiff` (added, retired, moved with from/to, module changes, unchanged count).
  `GET …/scene/reflow/preview` (analyst) computes the reflow without storing it and returns a `preview_digest`;
  `POST …/scene/reflow` accepts that digest and refuses a stale preview with 409. `GET …/scene/layouts` (viewer).
- **Search (LP16-A3).** Every index entry carries state (`current` / `archived`), incarnation and a search text (name,
  id, aliases, owner, provider identity, path — never findings or activity). `searchWorld()` returns an honest total;
  `GET …/scene/search?q=&limit=` reports `truncated`. Helpers `hierarchyNodes`, `hierarchyTrail`, `structureNodeFor`,
  `SEMANTIC_LEVELS`, `semanticLevelForScale`.
- **Console.**
  - World tab in the Kingdom sidebar (`WorldNavigator.tsx`): realm › environment › account › district › structure
    with stable ids, breadcrumb trail, *Previous focus* (browser Back), complete per-district membership lists,
    archived-placement toggle, search over every asset and archived incarnation.
  - Shared world focus: `#wf=<hierarchy id>` navigation state, consumed by the castle (frames the node, opens the
    aggregated district at > 50 assets; a single structure is framed with a zoom cap so neighbours stay visible) and by
    the 2D graph (opens the district; marks members). A search result in another district moves the focus to that
    structure.
  - Semantic zoom: the castle publishes `data-semantic-level` and a toolbar chip; the label budget follows the level
    (distant levels suppress label detail, never findings or unobserved resources; grouped assets stay listed).
  - View label: `Current · graph <rev> · layout v<n>` / `Historical · as known|occurred at … · coverage remains
    current` / `Branch · …` (branch mode is wired for LP19); the replay tag names the time basis.
  - Archived placements: dashed footprint outline plus a front-edge label, only on explicit request; no hit proxy, no
    status. The asset inspector shows the current incarnation and an *Earlier incarnations* list; a removed asset's
    record lists its archived placements.
  - Case scope (LP16-A4): `#case=<id>` navigation state; opening a case in Cases sets it; a toolbar chip shows the case
    title and scoped-asset count in every Kingdom view.
- MCP `dk_world_locate` (search or locate; parameter named `text`, not `query`, per the LP09 parameter policy) returns
  the same JSON as the API.

## Limits

- Semantic levels are a function of orthographic scale; there is no separate interior render yet (LP18 adds it).
- Archived placements are the last compiled positions; a recreated asset may legitimately occupy the same slot, so the
  outline can coincide with the live building (the label is offset to the footprint edge).
- Under heavy shared-machine load the 200-asset SwiftShader scene can stall the main thread for several seconds; the
  spec waits for a settled camera before interacting. Software WebGL only; not a GPU benchmark.
- No model call; AI execution not exercised.
