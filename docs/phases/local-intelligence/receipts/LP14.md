Milestone M3, branch `phase/li-m3` (worktree `DK-m3`). Builds on LP13 (analysis state, candidate application,
comparisons, path explanation) and LP01 (evaluator `dk.aws_policy_eval.v2`). Commit and CI run are recorded in

Reused: LP13 `exploration.ts` (`applyChanges`, `compareStates`, `explainPath`, `graphFromState`,

## What changed

- Contract `dk.local.repair_plan.v1` (`packages/contracts/schemas/local/repair-plan.v1.schema.json`,
  `packages/contracts/src/repair.ts`, generated `validateRepairPlan`): adopted from
  `dk.local.repair_plan.proposed.v1` by dropping `proposed`; `authority` is the constant `plan_only`; five finite
  action types (`set_gateway_policy`, `deactivate_test_token`, `remove_test_grant`, `select_test_artifact`,
  `restart_test_observer`) each taking exactly one reference parameter; every object rejects unknown fields (no
  command/script/url/endpoint/host/token/credential/env anywhere); semantic checks: unique action ids, the right
  parameter per type, candidate digest ≠ baseline digest, positive controls disjoint from verification tests, expiry.
- `apps/server/src/repair.ts` — `dk.repair_candidates.v1`:
  - Five reviewed templates (`dk.repair_templates.v1`, a code constant, never runtime input) mapped one-to-one to
    the action types, each with disruption class, reversibility and prerequisites (incl. "a local lab lease (LP16;
    none exists in this phase)").
  - Objective = prohibited operations (must become impossible) and permitted operations (positive controls; at least
    one required). Probe kinds: `permission` (LP01 evaluator, plus `evaluateWithCredentials`: a user whose every key is
    Inactive has no usable key), `path` (declared graph path; a tool link whose gateway is `deny` is not a path),
    `observer_gap`, `artifact_version`.
  - Each template proposal is applied in an analysis namespace `repair:<digest>` (never the baseline) and
    re-evaluated: expected impact per probe (before/after), positive controls, verification (model-only result;
    executed-local pending LP16; external deferred EXT01), compensation (exact inverse changes), a validated
    plan-only repair plan bound to `baseline_digest` = LP13 base state hash and `candidate_digest` = candidate state
    hash, and a `dk.config_patch.v1` patch (baseline state hash, graph revision, snapshot id + digest, source
    revisions, artifact references, per-file before/after sha256, unified diff, patch digest).
  - Ranking on recorded criteria only — validity, objective coverage, positive controls broken, unknowns, elements
    changed — with the note that it is not a claim of global optimality. Outcomes: `candidates` (≥ 2 valid),
    `single_candidate`, `no_supported_repair` (with reasons per prohibited operation), `no_repair_needed`.
  - Storage `repair_candidate_sets` (migration `REPAIR_MIGRATION`, append-only triggers). Routes:
    `GET /api/repairs/templates`, `POST /api/projects/:p/cases/:id/repairs` (analyst; `base_state_hash` 428/409),
    `GET …/repairs/:sid` (viewer), `GET …/repairs/:sid/candidates/:cid/patch` (download), `POST
    …/candidates/:cid/authorization-check` (answers only whether an approval descriptor still binds plan id,
    baseline digest, candidate digest, current baseline and expiry; `authorizes_execution` is always false). No
    apply / publish / pull-request / execute route exists.
  - `materializePatch` writes a patch only into a new `mkdtemp` directory outside the operator checkout (refuses the
    checkout and any directory inside it, refuses paths escaping the directory, runs nothing).
- `exploration.ts`: credential elements (key id + status only; secret values never exist), tool `gateway` /
  `policy_ref` attributes, and `evaluateWithCredentials` in comparisons.
- Workbench: `repair_candidates` (latest set for the case, summary only) and a tradeoff table in `CaseWorkbench.tsx`.

## Limits

- Model-only. Nothing is applied, executed or observed; executed-local verification needs LP16 (lab lease) and
  external effectiveness is deferred (EXT01). Human approval recording is deferred (EXT05).
- Templates act only on declared, run-owned test elements (identity-policy statements, access keys, agent tool
  links, deployed artifact versions, observers). Resource policies, SCPs, boundaries and trust policies have no
  reviewed template yet; such objectives return `no_supported_repair` with the reason.
- Permission semantics are the LP01 evaluator's (S3 and `sts:AssumeRole`; conditions not evaluated); paths are
  declared reachability.
- No model call; AI execution not exercised.
