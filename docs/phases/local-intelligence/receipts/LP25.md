# LP25 — Private truth and admissible-evidence grading (receipt)

Milestone M6, branch `phase/li-m6` (worktree `DK-m6`). Builds on LP24's controller and LP07's private truth.

Reused: LP07 `PrivateTruth` (executed operations with status and the services' effect tap log, written 0600 in the
run directory), the scenario DSL validators (`parseScenario`, `checkScenarioAgainstWorld`), `seedCommitment`, the LP04
compiled world's observation table (which observer the world builder attached to which resource), and blueprint
accounts/resources. The referee deliberately does NOT reuse any Digital Kingdom detector, finding, coverage, packet,
contract or claim-check helper (the product under test).

## What changed

- `eval/local/referee.ts` (`li-referee-1`) — `answerKey(family, doc, truth, world)`:
  - **World truth** per in-scope operation (saas: tenant record reads; agent: gateway sends; delivery: credential uses):
    outcome from the executed status, effect from the supervisor tap log on the target resources, boundary violation from
    the schedule and blueprint (session account's tenant vs requested tenant; destination vs the reviewed approved
    receiver; grant/revocation state of the credential's subject at that point of the schedule).
  - **Admissibility** from the world builder's observer attachment and the schedule's faults only: observer stopped at
    the time → `independent_effect` admits only `unknown`; observer records silently dropped (or held and never released)
    → `not_observed` or `unknown` (evidence-consistent; world truth kept for divergence reporting); otherwise only the
    world value. Boundary admits `unknown` too unless a delivered record establishes the decisive fact. An operation
    whose self-reports were all lost is not visible and is excluded (reported as a coverage limitation).
  - `gradeAnswer` — deterministic: per predicate pass/fail, a missing operation fails all three predicates, extraneous
    operations listed, `unsupported_affirmatives` (a non-unknown value outside the admissible set), and
    `world_divergence` (accepted answers that differ from world truth because the fact was not observable).
  - `logicalKey` — the key by schedule position, independent of run/op ids and resource names.
- `eval/local/heldout.ts` (`li-heldout-gen-1`) — seeded held-out generator per blueprint with truth-changing toggles
  (actor direction, baseline attempts, weak policy, delayed/dropped evidence, observer outages, grants/revocations);
  random ids/run ids/artifact names, no labels and no expectations in the document. `materializeHeldout` writes the
  master seed and documents 0600 into a 0700 private directory under the OS temp root (outside the repository) and
  returns only commitments (SHA-256 of canonical JSON + seed commitment); `loadHeldout` refuses a document that no
  longer matches its commitment. `renameSaas` renames every resource (via a renamed world plan), sources, observers and
  labels and jitters timing without changing the controlled operations.
- `eval/local/native-agent.ts` now grades a native agent's answer with the referee (LP24 recorded it ungraded).
- Leakage canaries (LP24 controller): a random canary exists only in the private oracle file and controller memory;
  `privateMarkers` = canary, seed, scenario id, oracle and truth paths, labels; `leakScan` checks prompts and every tool
  response (used per attempt in LP26; a hit invalidates the attempt as `leak_invalidated`).

## Tests (executed) — `eval/test/li-lp25-private-truth.test.ts`, 8 tests

- **A1** (1): in C1 and C3 sessions (after an ordinary investigation), calls to `read_file` (oracle path),
  `dk_get_truth`, `dk_score`, `dk_get_seed` are refused and recorded as `unknown_tool` denials; `dk_inspect_refs` on the
  oracle path, a `../../scenarios/...` path, the seed, `private-truth` and the canary returns `found: false` (recorded
  `ref_not_found`); a seed-valued search filter returns nothing; no response the investigator did not itself prompt
  contains any private marker. HTTP with the investigator's token on truth/oracle/score/scenario/seed/referee paths and a
  traversal to the oracle file return 404/403 with no seed or canary; capabilities and snapshot carry no marker; the
  oracle file is 0600 outside the repository. Positive control: the scan detects a planted canary.
- **A2** (3): static — `referee.ts` imports no `apps/server`, `apps/mcp`, detections, investigation, claims, packets,
  coverage or findings module. Tamper — deleting the audit observer's record of the weak-policy cross-tenant read from
  the PRODUCT store (404 afterwards) leaves the key byte-identical, and the scripted investigator that trusts the product's
  now-partial evidence fails exactly that predicate (`not_observed` where `observed` is admissible), while the untampered
  evidence scores fully. Schedule — removing the revocation from LW-03 flips the last operation's key from
  denied/violation to allowed/no-violation/observed.
- **A3** (2): LW-01 outage read (world: observed) admits only `unknown`; `observed` and `not_observed` both fail and count
  as unsupported affirmatives; an observable fact answered `unknown` fails; a missing operation fails all three. LW-02
  dropped observer evidence (world: observed) admits `not_observed`/`unknown` and the accepted `not_observed` is reported as
  world divergence. Across 6 generated held-out variants, every operation after an observer stop admits only `unknown`,
  and the scripted baseline that sees only delivered evidence reaches the full score (nothing omniscient required).
- **A4** (2): LW-01 with every resource, source, observer and label renamed and timing jittered gives the same
  `logicalKey`, the same public task, a full scripted score through C3 and no leaked marker; public tasks name no label,
  seed, expectation, step position or answer-bearing word. Held-out documents have random `lh-…` ids, no labels or
  expectations, are deterministic from the master seed, live 0600/0700 outside the repository, and a tampered document is
  refused by its commitment; a private directory is never overwritten.

## Limits

- Admissibility rules are this phase's specification of "what could be established from authorized evidence"; they model
  observer stop/restart and delivery drop/delay/release, not every possible partial-coverage pattern.
- Resource renaming is exercised for the saas-storefront blueprint; the agent-workspace receivers keep their reviewed ids
  (the built-in gateway's baseline policy is keyed to the approved receiver id).
- Dev documents remain repository-resident (D-LP07-3); only generated held-out documents are private before seal.
- No model call in LP25; AI execution not exercised here.
