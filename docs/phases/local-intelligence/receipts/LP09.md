## What changed

- `apps/server/src/investigation/jobs.ts` (`InvestigationJobs`, schema `dk.investigation_job.v1`):
  - **Typed plans**: a job binds one contract revision; one step per open obligation (`search_activity`, `coverage`,
    `recipe`, `bundle_read`, `linked_events`) plus client-requested `pivot` steps. Client input is a closed set of
    fields (`budget {max_units, page_limit}`, pivot `{pivot_type, value, from_ref, after, before}`); forbidden names
    (sql, query, path, url, graph/cypher, credential, token, api_key, command, …) and unknown fields are refused with
    422.
  - **Scope-safe pivots**: `actor_ref`, `session_ref`, `run_id`, trusted `request_id`, `route`, in-scope `asset_id`; the
    value must be carried by an event already delivered under this contract (`from_ref`), the interval must lie inside
    the contract interval, and identity pivots keep only events in the origin event's declared correlation namespace
    (others are counted as `other_authority_excluded`).
  - **Committed units**: each unit (search page, coverage question, bundle page, recipe query) is fetched, then
    committed in ONE transaction with its deliveries (unique per job/step/ref), its cursor/snapshot/counters and the
    budget counter (and any obligation result, applied through `InvestigationContracts.applyResults`). A test-only
    `faultHook` throws inside that transaction to simulate a crash before commit.
  - **Quotas / budgets**: default 40 units, cap 200 per job (1000 total with extensions), ≤ 50 units per advance,
    page limit ≤ 100, ≤ 3 active jobs per case and ≤ 20 per project (429).
  - **Control**: cancel (analyst), budget extension (analyst), and every advance re-authorizes the caller AND checks
    the creating token is still valid (revoked → job `revoked`, no further units). An expired search cursor restarts
    that step under a new snapshot and records `cursor_restart`.
  - **Explicit incompleteness**: budget exhaustion → step `partial_budget`, obligation `partial` ("resumable"), job
    `budget_exhausted`, contract stays `collecting`; a page error → step and obligation `failed` (contract `blocked`, job
    `completed_with_errors`); records removed mid-pagination → step `partial` (not resumable). None mark an obligation
    satisfied. Per-step purpose, params, status, counters (units, pages, delivered, matched in snapshot, snapshot seq,
    other-authority excluded, restarts), completeness, error and result-applied are returned; job events are logged.
- `contracts.ts`: a result planned under an earlier contract revision still counts when that obligation's target and
  (for interval-bound obligations) the interval are unchanged since; otherwise it is refused and the step is `stale`.
  Contracts read the jobs' resumable obligations so a budget-cut `partial` keeps the contract `collecting`.
- Migration `INVESTIGATION_JOBS_MIGRATION` (jobs, steps, job events, delivery log); `hardening.test.ts` v0.2 rewind drops
  the new tables.
- Routes: `GET …/cases/:id/contract/plan` (viewer, read-only preview, persists nothing),
  `POST|GET …/cases/:id/jobs`, `GET /api/projects/:p/jobs/:jid`, `…/events`, `…/deliveries` (paged), and analyst
  writes `…/advance {max_units}`, `…/steps`, `…/budget {add_units}`, `…/cancel {reason}` (unknown fields 422).

## Limits

- Jobs advance only when a client calls advance (no background worker); that is deliberate (no hidden work) and the
  committed state makes any client able to continue.
- A search cursor expires after one hour; a resume after that restarts the step under a new snapshot (recorded) rather
  than continuing the old one.
- Recipe steps run a recipe as one unit group (its own query budget, capped by the job's remaining units); a
  budget-cut recipe re-runs from the start when the budget is extended.
- Pivot results are delivered evidence but satisfy no contract obligation (obligations come only from the contract).
