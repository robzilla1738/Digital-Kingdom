# LP29 — Local mission and scenario composer (receipt)

Milestone M7, worktree `DK-m7` (branch `phase/li-m7`), pushed directly to `phase/local-intelligence` as d3eb304.
Depends on LP07 (finite DSL), LP18 (world/interiors) and LP28 (capsules). CI is recorded in STATUS.json (`packages[LP29]`).

Reused: LP04 `getBlueprint`/`instantiateBlueprint`/`compileWorld`/`previewWorld` and the reviewed blueprint budgets, LP07

## What changed
- `packages/local-world/src/mission.ts` (`dk.local.mission.v1`): `composeMission(draft)` never throws for a bad draft; it
  returns the untouched draft with every issue (`created: false`). A valid draft compiles the blueprint world, validates
  the schedule against it, checks finiteness against the world budget (budgets can only be tightened), and splits into
  the builder `truth` (seed + whole schedule + labels/roles + expectations) and the investigator `brief` (mode,
  components, declared sources, synthetic identity count, budget preview, unknowns = world gaps, limitations,
  `truth_commitment = sha256(canonical truth)`, scope `local_only_synthetic_no_remote_setup`). Fault/mutation/distractor
  counts are builder-only. `parseMissionProposal` accepts an AI-assisted proposal only as one JSON object (no prose,
  code fences or code) and runs the same composer. `MISSION_STARTERS`: one seedless benign schedule per blueprint.
- `apps/server/src/missions.ts` (+ migration): `GET /api/local-missions/templates` (analyst; seedless starters, never a
  repository scenario document), `POST /api/local-missions/preview` (pure), `POST /api/local-missions` (analyst; stores
  the brief + commitment only; invalid → 422 with the draft echoed, `created:false`, `connected:false`; duplicate → 409),
  `GET /api/local-missions[/:id]` (viewer; investigator record, `truth_stored_on_server: false`, runtime from runner
  reports only), `POST /:id/open-truth` (analyst, reason required, audited; mission and runs become non-blinded),
  `POST /:id/cancel` (only before any run), runner lifecycle `POST /:id/runs` (admin; refused unless the runner's truth
  commitment and compiled world revision match) and `POST /:id/runs/:run/finish` (step-index accounting + cleanup outcome).
- `examples/reference-app/src/world/mission.ts` + `pnpm mission check|run <file> --mission <id>`: composes the file
  locally, checks the server commitment, starts a disposable world against that server, runs the LP07 schedule, reports
  lifecycle/accounting/cleanup (never labels, expectations or seed), stops and cleans up in `finally`.
- MCP `dk_local_missions` (read-only, equals the API record). Not added to the frozen `INVESTIGATION_TOOLS` list.
- Console: Integrations → **Missions** tab (`MissionDesk.tsx`): Builder (seedless starter with a seed drawn in the browser,
  mode, step table with remove/add from the finite vocabulary, JSON draft, Preview → budget preview + unknowns, Create,
  Cancel, Download mission file; errors keep the draft and say nothing was created or connected; the draft persists in
  the tab's sessionStorage) and Investigator (missions, brief, runs with accounting/cleanup/blinded, run command, cancel
  before start, explicit "open builder truth" gate). "Local only · synthetic data · no remote setup" badge throughout.
- Visual defect found by inspecting the 390px screenshot and fixed: seven integration tabs overlapped labels
  ("Missions"/"Notifications"); the tab list now scrolls horizontally below 768px.
- `apps/server/test/hardening.test.ts`: the v0.2-upgrade fixture also drops the two new tables (same pattern as every
  earlier migration); assertions unchanged.

## Limits
- The console never starts processes: a run is started with `pnpm mission run` (admin token) on the operator's machine;
  the UI shows the command and the lifecycle the runner reports. No in-browser start/pause/resume.
- Missions are not yet packaged as LP28 capsules (the capsule layout carries a case export; a mission run's lab project
  can be exported through the existing case capsule route). No console capsule export/import button was added.
- The builder draft (private truth) lives in the browser tab's sessionStorage and the downloaded file; the server holds
  only the commitment. "Open truth" records the taint; the truth itself is shown only in the builder view.
- No model call; AI-assisted proposals are validated as data, AI execution not exercised. Software WebGL only.
