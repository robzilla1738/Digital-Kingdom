# LP03 — Define run provenance and capability contracts (receipt)

Reused: `@dk/contracts` schema + precompiled-validator pipeline (`scripts/generate-validators.ts`), R06.2 surface
registry and `SUPPORT_LEVELS`, R02.1 connector capability levels (unchanged), R07.1 control verification records,
`projects.meta`. Design and migration notes: `docs/phases/local-intelligence/CONTRACTS.md`.

## What changed

- New schemas `packages/contracts/schemas/local/{world-plan,run-provenance,verification-receipt,capability-receipt}.v1.schema.json`
  (world-plan and verification-receipt adopted from the package proposals with ids `dk.local.*.v1`), compiled into
  `src/generated/validators.js`; semantic validators and `deriveCapability` in `packages/contracts/src/local.ts`.
- `POST /api/projects` accepts an optional validated `local_run`; `apps/server/src/provenance.ts` derives a
  `provenance` object that is returned by projects list, snapshot, overview, event search, event detail, bundle
  events, recipe runs, and inside the signed manifests of finding and case exports (and so through MCP).
- `GET /api/projects/:p/surfaces` adds per-asset `capability` derived only from scoped receipts built from project
  records (graph declaration, source delivery, tested control in a local-run project); `support` is kept unchanged as
  the registry ceiling. `/api/capabilities` lists the local contract ids and the access evaluator version.
- Console: "Local lab" pill (TopBar) and a local laboratory banner (Shell) for local-run projects.
- Reference pack creates its project with local run provenance (dataset_kind still `live`).

  `local_run: false`; local provenance never changes dataset_kind; invalid stored record not relabelled; package
  examples validate only after the explicit id migration.
  A3 package negative fixtures rejected; 17 forbidden field names at every object level of all four contracts rejected;

  A2 qualifiers on 9 API surfaces (incl. both exports) and on MCP overview/search/event; invalid `local_run` → 422.
  A4 lab_verified family with no receipts → `rendered`; model-authored / out-of-scope / mismatched receipts rejected;
  external validation rejected (EXT01); ceiling cap; tier mapping total; surfaces API from real records (source
  delivery → instrumented; tested control lifts only the local-run project).
- `apps/web/src/panels/localProvenance.test.ts` — 2 tests: TopBar pill rendered only for local runs with the dataset
  pill unchanged; snapshot provenance reaches the web dataset.

## Limits

- Provenance is project-level. A project mixing fixture delivery and runtime events cannot yet label them per event;
  the migration path is recorded in CONTRACTS.md.
- The Shell banner is covered by source + the TopBar render test, not by a browser screenshot in this package
  (Playwright not run locally; CI browser-pilot runs the existing specs).
- `investigation-contract`, `conclusion` and `repair-plan` proposals are deliberately left for LP04+.
