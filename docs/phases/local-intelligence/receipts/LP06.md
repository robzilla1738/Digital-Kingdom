# LP06 — Run instrumented services and independent observers (receipt)

Reused: the reference app's instrumentation pattern (`examples/reference-app/src/app.ts`), the agent boundary's
intent → decision → execution → independent effect split (`src/agent/boundary.ts`), `@dk/sdk-node` (unchanged) for
every source, ordinary authenticated ingestion (`/ingest/events`), server-side source capabilities and independence
groups (`@dk/detections`), coverage history (R01.2), the agent effect rule (R05.1), the MCP server (unchanged) and
the console's own `loadFromServer`. LP05 supervisor; LP03 `dk.local.verification_receipt.v1`.

## What changed

- `examples/reference-app/src/world/services.ts` — built-in services for every non-observer template (`gateway`,
  `auth`, `api`, `tenant_store`, `queue`, `worker`, `artifact_depot`, `agent_gateway`, `receiver`, `local_issuer`)
  with controlled synthetic data (seeded tenant records, synthetic passwords/credentials labelled synthetic). Each
  reports through its own self-report source; effect points (store reads/writes, queue, artifact publish/select,
  receiver delivery) go through the effect tap to the independent observer. Policy variants
  (baseline/candidate/deliberately_weak) are typed; revisions like `api:policy-baseline-r1` identify them.
- `src/world/session.ts` — `startLocalWorld`: supervisor run + `provision` (lab project with local run provenance,
  compiled graph, one source per declared source with its kind, asset scope, independence group and namespaces,
  one SDK key each) + `ReporterHub` (evidence path, with hold/release/drop faults for LP07).
- `src/world/cli.ts` + `pnpm world [--blueprint …] [--seed …] [--once]` — isolated server + world, prints run,
  supervisor-allocated endpoints, in-process services, observers, preflight controls, one benign operation and the
  per-capability reporting table; cleans up on exit.
- `packages/local-world/src/runtime/observer.ts` — `EffectObserver` (per-operation records with run/resource
  identity and resource revision, health intervals, `answer(op, interval, resource, settle)` → observed /
  not_observed only when up throughout / unknown; effects of an agent run carry the run id).
- `runtime/verify.ts` — `probeOf` / `verificationReceipt` (validated `dk.local.verification_receipt.v1`; unknown
  effect ⇒ inconclusive; failed cleanup keeps overall from passing) and `corroboration` by registered source kind and
  independence group only.
- `runtime/supervisor.ts` — background `tick` (worker drains while running or paused), `settle`, typed `configure`
  (policy variant only, recorded in private truth).
- Catalog `dk-local-catalog-2`: `local_issuer` 1.1.0 adds `POST /credentials/verify`; `artifact_depot` 1.1.0 adds
  `GET/POST /deployed`. catalog-1 was only ever compiled for previews (LP04).
- Server: `GET /api/projects/:p/local-world/reporting` (`dk.local.reporting.v1`) — every declared (source, asset,
  action) capability from the registered source record, with `reporting` / `silent` / `unavailable` / `disabled`,
  counts, last event, coverage state, outage health, rejections.
- Console: Integrations → "Local world" tab (`LocalWorld.tsx`): blueprint preview (resources, declared sources with
  role and group, gaps, limitations, budget) and the reporting table for local-run projects; it never launches
  processes. `ServerActions` gains optional `localWorldPreview` / `localWorldReporting`.

## Limits

- "Browser" equivalence is the console's data loader in Node, not a Playwright screenshot of the new tab (the CI
  browser pilot runs the existing specs; no new e2e spec was added in this package).
- Self-report sources use their kind's default capability set (e.g. `edge` includes `waf_match`), so reporting lists
  some capabilities the built-in service never emits; they stay `silent`, which is accurate but noisy.
- The queue and retrieval store have no observer in their blueprints (declared gaps); the worker's job effects are
  observed at the store/depot taps.
- Observer outage is announced (`sensor_unavailable`) for deliberate stops; a crash-style silent outage is detected
  only by staleness and by the observer's own health intervals.
