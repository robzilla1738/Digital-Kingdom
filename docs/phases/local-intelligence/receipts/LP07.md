## What changed

- `packages/local-world/src/scenario/dsl.ts` — `dk.local.scenario.v1`: `parseScenario` (shape only) and
  `checkScenarioAgainstWorld` (every reference resolves in the compiled world). Fourteen finite actions
  (`sign_in`, `request_route`, `enqueue_job`, `agent_send`, `agent_search`, `issue_credential`, `use_credential`,
  `revoke_credential`, `change_grant`, `publish_artifact`, `select_artifact`, `set_policy`, `observer`,
  `evidence`); per-action required/optional fields; unknown keys rejected at the top level, in steps and in
  expectations; ids are plain ids (no URL, host, path); routes must be `GET|POST /declared/{template}` of the target
  resource's catalog template; parameters are single path segments; ordered `at_ms` within the world budget; roles
  `stimulus | distractor | mutation | fault` (`set_policy` is always a mutation, `observer`/`evidence` always faults);
  unique labels; expectations must name labelled steps. `fillRoute` fills only declared templates.
- `examples/reference-app/src/world/scenario.ts` — the engine: executes a validated schedule against ONE
  supervisor-owned run using only typed supervisor operations and the hub's hold/release/drop faults (no shell,
  plugin, script, eval or URL path). Three separate stores:
  - private truth (`dk.local.private_truth.v1`: seed, labels, expectations, every step record with scheduled offset,
    actual monotonic start/end offsets and scenario time, every effect from the run's tap log, lifecycle) written as
    a run-owned 0600 file inside the run directory;
  - observable evidence: whatever sources delivered to Digital Kingdom through ordinary ingestion;
  - investigator output: `investigatorView` built only from the Digital Kingdom API with a viewer token.
  The referee grades from private truth plus independent observers only, never from Digital Kingdom's derived
  conclusions. `ScenarioResult` carries accounting (executed / refused / failed / not_run with step indexes), timing
  (scheduled span, actual span, max lag, time scale) and per-label grades; a stopped schedule, budget refusal or
  failure makes it `partial`, never `complete`. `intendedState`/`intendedDigest` compare runs independent of run
  ids, op ids, random handles and timing. `leakCheck` searches a view for the seed, its commitment, the scenario
  id, labels, expectations, non-stimulus role markers and supplied secrets.
- `examples/reference-app/src/world/session.ts` — reporter events get their occurrence time when the source observes
  them, so a held (delayed) record keeps its real time and the delay shows only as receipt lag.
- Scenarios: `scenarios/local-world/LW-01..03.json` (`dk.scenario.v1` manifests, `execution: local`,
  `data_policy: synthetic_only`) pointing at DSL documents `scenarios/local-world/dsl/LW-0n.scenario.json`:
  LW-01 SaaS storefront tenant boundary through a policy change, audit-observer outage and delayed API evidence,
  with a benign tenant-b distractor; LW-02 agent delivery to a blocked receiver under a weakened tool policy with
  dropped observer evidence; LW-03 short-lived credential use with a grant change and deactivation.
  `scripts/run-scenarios.ts` now reads `scenarios/dk-t` and `scenarios/local-world`.

## Limits

- The DSL documents (seed, labels, expectations) and the LW manifests' expected observations live in this
  repository. Digital Kingdom's API, MCP and viewer cannot serve them (tested above), but an investigator agent with
  repository or filesystem access is not blinded; such a run must record that access and counts as development
  feedback, not a held-out evaluation. Held-out scenarios need truth stored outside the investigator's workspace
  (LP24+ evaluation harness).
- Runs execute in-process trusted built-in services (LP05 `trusted_builtin_processes`, reported restricted);
  container isolation stays refused.
- Time scale is wall-clock pacing of the schedule; services are not driven by scenario time (scenario time is
  recorded per step, separately from monotonic offsets).
- Three scenarios only; the DSL vocabulary covers the LP06 service catalog (`dk-local-catalog-2`) and no more.
- No model runs; AI execution not exercised (not needed for LP07).
