# LP23 — Capture a repair as a replayable regression (receipt)

Milestone M5, worktree `DK-m7` (branch `phase/li-m7`), pushed directly to `phase/local-intelligence`. Depends on LP22
(independent verification) and LP19 (world comparison). Commits: b4c6f4e (substage 1), 2c82242 (substage 2), ddab371
(legacy-upgrade test fix). CI is recorded in STATUS.json (`packages[LP23]`).

Reused: LP21 `RepairController` + LP20 leases (replay executes only the typed actions under a fresh supervisor lease
held by a separate controller identity), LP22 `EffectVerifier` (baseline + after-repair observations, finalize after
cleanup), LP04 `compileWorld`/`instantiateBlueprint` (world rebuilt from blueprint + public seed; template
versions/digests and catalog digest pinned), LP06 built-in services (synthetic sign-in), R03.1 case closure rules,
LP13 comparisons and the LP19 world view. The R07.4 detection-rule regression proposals (`apps/server/src/regression.ts`)
are unchanged: they minimize detector events into rule fixtures; LP23 descriptors are their local-lab counterpart for
executed repairs and follow the same principles (minimized, synthetic, corrected-vs-broken condition, no automatic
publication, "a passing regression is not a validated defence").

## What changed
- Contract `dk.local.repair_regression.v1` (`packages/contracts/schemas/local/repair-regression.v1.schema.json`,
  `validateRepairRegression` in `packages/contracts/src/lab.ts`): world (blueprint, version, public seed, plan and
  catalog digests), typed defect prerequisite (`policy_variant`), principals as synthetic account refs, typed repair
  actions (exactly the type's one reference parameter), negative/positive controls (prohibited ⇔ negative), expected
  baseline (all observed), without-repair (prohibited observed) and after-repair (pass / success, no residual access,
  no disruption), pinned policy/tool/artifact versions, linkage digests (case ref, controls, plan, execution receipt,
  verification), residual uncertainty, replay constants (`llm: not_used`, `private_truth: not_included`,
  `scope: local_run_only`), descriptor digest. `additionalProperties: false` throughout: no field for headers, bodies,
  commands, URLs, secrets or oracle data.
- `packages/local-world/src/runtime/regression.ts`: `captureRegression` (refuses anything but a whole-run success with
  a pre-repair baseline, a verification/execution of another plan or receipt, probes whose headers are not exactly a
  declared principal, request bodies, resources outside the world; scans the canonical descriptor for every run secret
  the caller holds, run/operation ids and secret shapes — session tokens, synthetic passwords, tokens, keys, JWTs,
  emails, IPs, URLs, ARNs, host paths — and private-truth vocabulary), `checkRegression` (scan + schema + semantics +
  digest; digest described as integrity only), `regressionValidity` (world plan/catalog, pinned resource template
  version/digest, tool versions `LOCAL_REGRESSION_TOOLS`, pinned artifact digests → `stale` with the changed items).
- `examples/reference-app/src/lab/regression-replay.ts` — `replayRegression`: model-free, fresh disposable run per
  replay; stale descriptors are reported and not replayed; baseline must reproduce, without-repair must still show the
  prohibited effect, the typed repair (pinned target revision checked) must verify pass with whole-run success after
  cleanup. `examples/reference-app/capture-lr01.ts` regenerates the committed fixture
  `scenarios/local-world/regressions/LR-01-saas-cross-tenant-api.json` and the server-test verification fixtures from
  real lab runs.
- Server (`apps/server/src/local-repairs.ts`, migration `local_repair_links`): `POST/GET /api/projects/:p/cases/:id/local-repairs`
  (analyst; validates the LP22 verification and, optionally, the regression, which must have been captured from that
  verification; optional `comparison_id`), `POST /api/projects/:p/local-regressions/check` (re-checks every linked
  regression against the current code's world and reported tool/artifact versions; stale is sticky and audited).
  `Cases.setStatus` closure gate: a linked verification that is not a whole-run success, or a stale regression, blocks
  closing/resolving until accepted as an explicit unknown with a non-empty reason; the closure records
  `accepted_unknowns`. Open questions still block as before.
- LP19 gap closed: `dk.world_comparison.v1` `executed_local.results` lists verifications linked to the comparison
  (`executed: true`, `verified` only for whole-run success, verdict, whole run, tested revision, residual access,
  disruption, cleanup, `local_run_only`), separate from model-only results; the castle overlay lists them.

## Limits
- Replay supports session principals and policy-variant defects (the saas-storefront family); credential/grant
  defects (delivery-identity) can be captured in principle but their principals need typed credential setup, which is
  not implemented — capture refuses headers that are not a declared session principal.
- Regressions are linked by an analyst from lab output; the server never runs a replay. A stale validation becomes
  current only by linking a new passing replay (not automated).
- 2D-graph comparison overlay still not implemented (castle overlay lists executed-local runs).
- Local synthetic lab only; external effectiveness stays deferred (EXT01). No model call; AI execution not exercised.
