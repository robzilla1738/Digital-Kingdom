Reused/inspected: R07.2 lab runner (`examples/reference-app/src/lab/runner.ts`: budgets, abort, positive control,
inconclusive-on-unavailable semantics), the reference pack's loopback-only binding and reset, LP04 compiled worlds,

## Negative test first

`examples/reference-app/lp05-legacy-runner.test.ts` reproduced the foundation defect named in the phase spec §3:
`refuseTarget` admits ANY `127.0.0.1` listener (an unrelated local service the lab never created "passes" a lab test),
and its observer is an aggregate counter. It failed before the change (`target_ownership` undefined). The runner is
kept for its R07.2 control tests, but every receipt now carries `target_ownership: "unverified_url_allowlist"` and
says so in `conditions`. Owned runs use the new supervisor.

## What changed (`packages/local-world/src/runtime/`)

- `supervisor.ts` — `Supervisor` / `Run`:
  - run-owned identity: `run-<12 hex>`, project `lab-<12 hex>`, private 0700 directory under a supervisor-created
    `dk-lab-*` root, manifest `dk.local.run_manifest.v1` (supervisor pid, listeners with nonce digests — never
    nonces — in-process services, observers, token ids, owned paths, clone origin).
  - endpoint registry: the supervisor binds each routed built-in service on `127.0.0.1:0` itself; plans never name
    endpoints; a hand-edited compiled world is ignored (only the plan is recompiled and used).
  - nonce handshake per endpoint (HMAC challenge) re-verified before every action; every operation id is signed
    with the endpoint nonce so the listener refuses unsigned local requests.
  - `request(token, {resource, method, path})`: registered resource id + declared template route only; relative
    path, no `//`, `..`, encoded slashes, schemes; private `http.Agent` (no ambient proxy); effective peer checked;
    3xx refused and never followed; only `x-world-*` caller headers pass; request/parallel/byte budgets reserved
    synchronously.
  - inter-service calls only to declared dependencies, through the same registry path.
  - run tokens `dkrun_v1.<run>.<id>.<hmac>` with explicit resource/action scope; wrong run, forged signature,
    revoked, out-of-scope and non-lab project all refused; env vars, headers and project labels grant nothing.
  - lifecycle: start, pause (stimulus only), resume, snapshot/reset, clone (new ids/endpoints/nonces/tokens/dir from
    source state), stop, abort (revokes tokens, closes listeners), fault `loseListener`.
  - monotonic deadline (`process.hrtime`) with a watchdog; `ScenarioClock` is never consulted for enforcement.
  - `cleanup()`: manifest-owned paths only, reverse order, idempotent; never follows symlinks, refuses hard links and
    escaping canonical parents, leaves unowned entries; failures recorded; `operationalOutcome()` reports
    `cleanup_failed` separately from any security result.
- `isolation.ts` — `preflight` (`dk.local.preflight.v1`): each control is `enforced` / `checked` / `not_enforced` /
  `not_applicable`; host mode is explicitly `restricted` (built-in declarative services only, arbitrary execution
  disabled, OS egress and isolation boundary not enforced — stated, not implied); `operator_isolated_containers` is
  refused (launcher handshake not implemented; no container runtime or Docker socket is used); missing built-in
  implementations, concurrent-run limit and memory ceiling refuse. `containerProfile(plan)` generates the reviewable
  operator profile (internal network, read-only, non-root, cap_drop ALL, no-new-privileges, no ports/volumes/
  host network/docker.sock, pids/mem/cpu limits).
- `address.ts` — destination classes (loopback, metadata incl. `fd00:ec2::254`, link-local, RFC1918, CGNAT,
  multicast/reserved, public, IPv4-mapped IPv6, hostnames, ambiguous numeric spellings) and `refuseDestination`.
- `observer.ts` — `EffectObserver` (used by LP06), created by the run for each enabled observer in the plan.

## Limits

- Trusted host-process mode is the only executable mode. Built-in services share the supervisor process; OS-level
  egress filtering, CPU quotas and memory cgroups are not enforced (reported as such). It must not host untrusted or
  generated code.
- The optional container profile is generated and reviewed only; launching and verifying it is the operator's job
  and its handshake integration is not implemented, so that mode is refused rather than claimed.
- The supervisor is a library used by local tests, the scenario engine and the CLI; the Digital Kingdom server
  exposes no run-control endpoint, and `/api/capabilities.runtime_policy.local_actions` stays `plan_only`.
