# LP21 — Execute typed local repairs (receipt)

Milestone M5, branch `phase/li-m5` (worktree `DK-m5`). Depends on LP20 (leases) and LP06 (built-in services,
observers). Commit and CI run are recorded in STATUS.json (`packages[LP21]`).

Reused: the LP05 supervisor's registry-resolved, handshake-verified, proxy-free, redirect-refusing `send` (the only
way the controller's operations reach a service), declared-route checks (`assertRoute`), run budgets, run-owned
directory/manifest/cleanup and private truth; LP06 built-in services (policy variants, local issuer credentials and
grants, artifact depot); LP14's five action types and `dk.local.repair_plan.v1`; LP20 leases.

## What changed

- Contract `dk.local.repair_execution.v1` (`packages/contracts/schemas/local/repair-execution.v1.schema.json`,
  `validateRepairExecution` in `packages/contracts/src/lab.ts`): execution state (`completed`,
  `partially_applied`, `failed`, `cancelled`, `refused`), per-action state/from-to revision/operation id/idempotency
  key/apply count/reason, compensation outcomes, revisions before/after, untargeted changes, quota, cancellation,
  crash recovery, cleanup; `counts_as_human_approval: false`, `scope: local_run_only`. Semantic checks (completed ⇒
  every action done; applied/reconciled ⇒ apply_count 1 and a to-revision; cancelled actions ⇒ recorded
  cancellation). It is explicitly not a security verdict.
- `packages/local-world/src/runtime/repair-ops.ts` — the five reviewed typed operations (resolve the reference in the
  run's own state, desired-state predicate, pre-state capture, one fixed operation, compensation):
  `set_gateway_policy` (typed reconfigure to `baseline|candidate` of a gateway/agent gateway/API),
  `deactivate_test_token` (`POST /credentials/{id}/revoke` on the run's local issuer), `remove_test_grant`
  (`POST /grants` remove, reference `grant-<12 hex>` of subject|grant), `select_test_artifact` (`POST /deployed` of an
  existing digest), `restart_test_observer`. Compensation restores only a reviewed gateway policy; a deactivated
  token, a removed grant, a previously deployed artifact and a weak policy are `not_restored` (restoring them would
  restore the compromised authority).
- `supervisor.ts` (`Run`): `leasedOperation` (controller identity → lease check → resolve → pre-state capture by the
  run → lease use recorded → apply via the op table → new revision → `confirmApplied`; truth `repair_operation`),
  `repairObservation` (actual state for reconciliation), `compensateAction` (from the run-captured pre-state only),
  `relinquishLease`, `leaseOf`, and a run-owned append-only `repair-journal.jsonl` (1 MB budget, registered in the
  manifest, removed by cleanup).
- `packages/local-world/src/runtime/controller.ts` — `RepairController`: journalled state machine (`started` /
  `resumed`, `planned`, `applying`, `applied`, `reconciled`, `not_applied_before_crash`, `already_in_desired_state`,
  `refused`, `failed`, `cancelled`, `compensation`, `receipt`), idempotent re-execution, crash reconciliation from
  actual state, cancellation (stop new actions, give the lease up, no rollback), quota and refusal surfacing,
  compensation of reversible actions on partial application, `withRunCleanup` for the run owner's cleanup outcome.
  Refuses non-active leases up front. Imports nothing but contracts, catalog, lease and supervisor types.
- `examples/reference-app/src/world/services.ts`: the local issuer's revision now also reflects deactivated
  credentials (`issuer:grants-<h>-inactive-<h>`), so a deactivation is a revision change.
- `examples/reference-app/repair-lab.ts`: shared harness for LP21/LP22 tests (leased supervisor, operator
  credential, controller identity, plan builder, compromised/legitimate credential and weakened-storefront setups).

The server is unchanged and has no executor (`/api/capabilities` still `plan_only`); the controller is a library
used by the launcher inside a disposable run.

## Limits

- Trusted host-process mode only (LP05): the controller, supervisor and services share one process; the separate
  controller identity is a capability boundary inside it, not OS isolation.
- Compensation is limited to reviewed gateway policies; everything else requires a new reviewed plan and lease.
- Execution success is not defense: LP22 verifies effects independently.
- No model call; AI execution not exercised.
